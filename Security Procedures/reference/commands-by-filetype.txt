WHAT THIS IS
------------
A lookup table, not a procedure. When you have a thing in front of you and
need the command, it is here, grouped by what the thing is. The procedures in
triage/stage-*/procedure.txt tell you the order and the reasoning; this file
tells you the syntax.

Placeholders: <file> <url> <host> <id> <n> <ip>

===========================================================================
URL / HOSTNAME
===========================================================================
Decode                python3 -c "from urllib.parse import unquote; print(unquote('<url>'))"
Punycode/IDN          python3 -c "print('<host>'.encode().decode('idna'))"

Reverse DNS           dig +short -x <ip>

WHOIS                 whois <host>
Creation date only    whois <host> | grep -i 'creat'

Fetch body (no exec)  curl -s -o page.html "<url>"

Typosquats of a brand dnstwist --registered <brand>.com

EMAIL (.eml)
===========================================================================

ANY FILE - IDENTIFY FIRST
===========================================================================
Real type             file <file>
Type, terse           file -b <file>
Hashes                shasum -a 256 <file>   /   md5 -q <file>
                      sha256sum <file>       # Linux
Metadata              exiftool <file>
Metadata to CSV       exiftool -csv *.doc > metadata.csv
Provenance (macOS)    xattr -l <file>
Lock against change   chflags uchg <file>
Fuzzy hash            ssdeep <file>
Compare to known bad  ssdeep -m known_bad.hash <file>
Hidden/appended data  binwalk <file>
Extract everything    binwalk -Me <file>
Readable strings      strings <file> | less
Obfuscated strings    floss <file>
YARA match            yara -s rules.yar <file>
YARA recursive        yara -r rules/ ./samples/

Real type disagreeing with the extension is a finding, not a nuisance.

===========================================================================
PDF
===========================================================================
Risky tag triage      pdfid.py <file> -n
All tags              pdfid.py <file>
Structure             pdf-parser.py <file> -a
Include object streams pdf-parser.py <file> -a -O
One object            pdf-parser.py <file> -o <id>
Decode its stream     pdf-parser.py <file> -o <id> -d
What references it    pdf-parser.py <file> -r <id>
Interactive shell     peepdf -fl <file>      # then: tree, object <id>, js
Document info         mutool info <file>
Show one object       mutool show <file> <id>
Extract embedded      mutool extract <file>
Normalise/decompress  mutool clean <file> out.pdf
Decrypt (empty pw)    qpdf --password="" --decrypt <file> out.pdf
Decrypt (known pw)    qpdf --password=<pw> --decrypt <file> out.pdf
Check for encryption  qpdf --check <file>
Text and links        pdftotext -layout <file> - | grep -Eo 'https?://[^ ]+'
YARA the streams      mutool extract <file> && yara rules/ extracted_*

Tags to escalate on, and what each means
  /OpenAction /AA     script or action runs automatically on open
  /JavaScript /JS     JavaScript the reader will execute
  /AcroForm /XFA      forms that can specify JavaScript
  /Launch             can launch a program or open another document
  /EmbeddedFile       carries another file inside
  /URI                accesses a resource by URL
  /SubmitForm /GoToR  can send data to a URL
  /GoTo               changes view to a destination in this or another PDF
  /RichMedia          can embed Flash
  /ObjStm             object stream - can hide any of the above
  /XObject            can embed an image (phishing lure)

Names can be hex-escaped to evade a keyword scan: /J#61vaScript is
/JavaScript. If pdfid looks clean but the file arrived unexpectedly, read the
structure with pdf-parser anyway.

Full triage one-liner
  pdfid.py <file> -n && pdf-parser.py <file> -a && exiftool <file>

===========================================================================
RTF
===========================================================================
Embedded objects      rtfobj <file>
Group listing         rtfdump.py <file>
Object groups only    rtfdump.py <file> -O
Extract one object    rtfdump.py <file> -s <n> -H -d > obj.bin
Identify it           file obj.bin
Its OLE streams       oledump.py obj.bin -i
XOR-encoded PE        python3 ~/tools/DidierStevens/xorsearch.py -W obj.bin
Carve it              binwalk obj.bin
YARA                  yara rules/ <file>

RTF supports no macros. It carries files as OLE1 objects and is the standard
vehicle for Office parser exploits - CVE-2017-11882 (Equation Editor) above
all. An Equation, OLE2Link, or Package object is the exploit shape. An MZ
header at a non-zero offset inside an extracted object is a hidden PE.

===========================================================================
HTML
===========================================================================
Links                 grep -Eo 'href="[^"]+"' page.html
Meta-refresh          grep -Ei '<meta[^>]+refresh' page.html
JS redirect           grep -Eo '(window\.)?location(\.href)?[[:space:]]*=' page.html
Smuggling indicators  grep -iE 'atob|fromCharCode|msSaveBlob|new Blob|unescape\(' page.html
Password field        grep -iE '<input[^>]+type=.?password' page.html
Extract base64 blobs  python3 -c "
import base64,re,sys
h=open(sys.argv[1]).read()
for i,b in enumerate(re.findall(r'[A-Za-z0-9+/]{100,}={0,2}',h)):
    try:
        open(f'smuggled_{i}.bin','wb').write(base64.b64decode(b))
        print('smuggled_%d.bin'%i)
    except Exception: pass
" page.html
Then identify them    file smuggled_*.bin

curl -L follows HTTP 3xx only. Meta-refresh and JavaScript redirects are
invisible to it - grep for them explicitly.

===========================================================================

===========================================================================
JAVASCRIPT (extracted from a PDF, HTML, or archive)
===========================================================================
Beautify              python3 -c "import jsbeautifier,sys;print(jsbeautifier.beautify(open(sys.argv[1]).read()))" <file> > pretty.js
Sandboxed analysis    box-js <file> --output-dir results/
  results/urls.json     URLs it tried to contact
  results/payload.*     files it tried to drop
  results/analysis.log  full execution trace
Instrument eval       echo 'var _e=eval; eval=function(x){print("[EVAL] "+x); return _e(x);};' > instr.js && cat pretty.js >> instr.js && js instr.js
Decode by hand        CyberChef: https://gchq.github.io/CyberChef
                      typical recipe: From Base64 > XOR > Inflate > From Charcode

Red flags: eval chains, fromCharCode, long hex blobs, ActiveXObject,
WScript.Shell.Run.

===========================================================================
SHELLCODE / EXTRACTED BINARY
===========================================================================
Emulate (x86)         speakeasy -t <file> -r -a x86
Emulate (x64)         speakeasy -t <file> -r -a x64
Dump allocated stage  speakeasy -t <file> -r -a x86 --dumpmem 0x<addr> stage2.bin
Find IOCs in trace    speakeasy -t <file> -r -a x86 | grep -E "(http|cmd|powershell)"
Disassemble           python3 -c "
from capstone import *
md=Cs(CS_ARCH_X86,CS_MODE_32)
for i in md.disasm(open('<file>','rb').read(),0x1000):
    print('0x%x:\t%s\t%s'%(i.address,i.mnemonic,i.op_str))" | head -80
XOR-encoded search    xorsearch -W -d 3 <file>
Deobfuscated strings  floss <file>
Base64 blobs          base64dump.py <file>
Decode one            base64dump.py <file> -e bu -s <n> -d > decoded.bin
Numeric arrays        numbers-to-string.py <file>

API calls that tell you what it does: VirtualAlloc (second stage),
LoadLibrary/GetProcAddress (API resolution), InternetOpen/HttpOpenRequest/
connect (C2), CreateProcess/WinExec/ShellExecute (execution).

This is past the boundary of triage. If you are here, the verdict is already
malicious - work in the lab: ../modules/detonation-lab/.

===========================================================================
CONTAINERS THIS TOOLKIT DOES NOT ROUTE YET
===========================================================================
.lnk, .iso/.img/.vhd, .chm, .xll, .one (OneNote), and password-protected
archives are all current delivery wrappers with no branch in stage 2.
Treat them as samples for the lab, not as documents. Starting points:

Archive listing       unzip -l <file>   /   7z l <file>
Archive with password unzip -P <pw> <file> -d unzipped/
Then identify         file unzipped/*
Disk image (macOS)    hdiutil attach -nobrowse -readonly <file>
                      # inspect, then: hdiutil detach /Volumes/<name>
Anything else         binwalk -Me <file>
