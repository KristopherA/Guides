SERVICE CONTROL
================================================================================

COMMAND
  su - zimbra

DESCRIPTION
  Switches to the zimbra user with its full environment and PATH. Every zm* command expects this; running them as root fails or leaves root-owned files behind.

USAGE
  sudo su - zimbra

SUCCESS
  zimbra@mail:~$

FAILURE
  su: user zimbra does not exist
  (You are on the wrong host - confirm with hostname -f that you are on mail.example.com.)

COMMAND
  zmcontrol restart

DESCRIPTION
  Stops and starts every Zimbra service in order. Expect several minutes of downtime and every client disconnecting, so prefer restarting a single service in business hours.

USAGE

          Stopping mailbox...Done.
          ...
          Starting mailbox...Done.
          Starting proxy...Done.

FAILURE
  Error: must be run as user zimbra
  (You ran it as root. Run su - zimbra first.)

COMMAND
  zmmailbox -z -m <shared> mfg <folder> account <delegate> <rights>

DESCRIPTION
  Grants a delegate rights on one folder of a shared mailbox. The letters are r read, w write, i insert, d delete, x workflow and a admin; grant /Sent separately or the delegate will not see sent mail.

USAGE
  zmmailbox -z -m reception@example.com mfg /Inbox account jsmith@example.com rwidx

SUCCESS
  (No output. Confirm with zmmailbox -z -m reception@example.com gfg /Inbox.)

FAILURE
  ERROR: mail.NO_SUCH_FOLDER (no such folder path: /inbox)
  (Folder paths are case sensitive - list them with gaf.)

---

COMMAND
  zmmailbox -z -m <delegate> cm <local-path> <owner> <remote-path>

DESCRIPTION
  Creates a mountpoint so the shared folder appears in the delegate's folder tree. For a whole account, the GUI route is Admin Console > Tools and Migration > Share Toolkit, which shares rwixd and can also configure send-as.

USAGE
  zmmailbox -z -m jsmith@example.com cm --view message "/Reception Inbox" reception@example.com /Inbox

SUCCESS
  4571
  (The new mountpoint's folder ID.)

FAILURE
  ERROR: mail.ALREADY_EXISTS (object with that name already exists: Reception Inbox)
  (A mountpoint already exists. Rename the path or remove the old one with df.)

COMMAND
  ip route show | grep <ip>   /   ip route del <ip>

DESCRIPTION
  On mail.example.com, fail2ban bans IPs by adding a route, so a banned IP shows in the routing table. Get the user's public IP, confirm the ban in Graylog, and then remove the route as root. This is the organization's documented unban method.

USAGE
  sudo ip route show | grep 203.0.113.10 && sudo ip route del 203.0.113.10

SUCCESS
  unreachable 203.0.113.10
  (Run the grep again afterwards: no output means the ban is gone.)

FAILURE
  RTNETLINK answers: No such process
  (There is no route ban for that IP. Check the fail2ban jails, then Snort on pfSense.)
