WIREGUARD ENTERPRISE ADMINISTRATOR’S HANDBOOK CHAPTER 11 SITE-TO-SITE
VPNS

=============================================================================== 1.
OBJECTIVE
===============================================================================

A site-to-site VPN securely connects two or more private networks over
the Internet so that systems communicate as if they were on the same
routed enterprise network.

===============================================================================
2. COMMON TOPOLOGIES
===============================================================================

Two Sites

Office A Internet Office B 10.60.0.0/16 <==== WireGuard Tunnel ====>
10.20.0.0/16

Hub and Spoke

              Headquarters
                    |
      +-------------+-------------+
      |             |             |

Branch A Branch B Branch C

===============================================================================
3. SERVER CONFIGURATION
===============================================================================

Headquarters

[Interface] Address = 10.100.0.1/24 ListenPort = 51820 PrivateKey =
HQ_PRIVATE_KEY

Branch Peer

[Peer] PublicKey = BRANCH_PUBLIC_KEY AllowedIPs =
10.100.0.2/32,10.20.0.0/16

Branch

[Interface] Address = 10.100.0.2/24 PrivateKey = BRANCH_PRIVATE_KEY

[Peer] PublicKey = HQ_PUBLIC_KEY Endpoint = vpn.example.com:51820
AllowedIPs = 10.60.0.0/16 PersistentKeepalive = 25

===============================================================================
4. ROUTING
===============================================================================

Enable forwarding

sysctl -w net.ipv4.ip_forward=1

Verify

ip route ip route get 10.20.10.15

Each site’s LAN gateway must know how to reach the remote subnet, either
through static routes or a dynamic routing protocol.

===============================================================================
5. FIREWALL
===============================================================================

Allow tunnel

iptables -A INPUT -p udp –dport 51820 -j ACCEPT

Allow routed traffic

iptables -A FORWARD -s 10.60.0.0/16 -d 10.20.0.0/16 -j ACCEPT iptables
-A FORWARD -s 10.20.0.0/16 -d 10.60.0.0/16 -j ACCEPT

===============================================================================
6. NAT VS ROUTING
===============================================================================

Preferred: Pure routing.

Use NAT only when: - Overlapping networks cannot be redesigned. -
Third-party environments require address translation.

===============================================================================
7. OVERLAPPING NETWORKS
===============================================================================

If both sites use:

192.168.1.0/24

Options

-   Renumber one site (best)
-   Use policy-based routing
-   Apply 1:1 NAT
-   Isolate through dedicated gateways

===============================================================================
8. VALIDATION
===============================================================================

wg

Routes

===============================================================================
9. TROUBLESHOOTING
===============================================================================

Handshake succeeds but no LAN access

Check: - Static routes - AllowedIPs - IP forwarding - FORWARD rules -
Remote firewall

One-way communication

Likely: Missing return route or asymmetric routing.

===============================================================================
10. HIGH AVAILABILITY
===============================================================================

Use redundant VPN gateways.

Internet | +———–+ | Firewall | +———–+ | +——–+ VRRP +——–+ | WG-1 | <———–>
| WG-2 | +——–+ +——–+

Regularly test failover.

===============================================================================
11. BEST PRACTICES
===============================================================================

-   Prefer routing over NAT.
-   Keep LAN addressing unique.
-   Document every routed subnet.
-   Monitor handshake age.
-   Backup WireGuard and firewall configuration.
-   Test disaster recovery regularly.
