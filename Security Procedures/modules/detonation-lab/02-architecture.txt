Malware Hunting Lab Architecture Diagram
========================================

Goal
----
Create a controlled architecture for malware hunting using containers, remote
access, staged sample handling, and detection-output generation.

Recommended zones
-----------------

1. Analyst Zone
   - Browser only.
   - No sample execution.
   - Accesses lab through gateway.

2. Intake Zone
   - Pulls samples from MalwareBazaar or other approved feeds.
   - Stores samples safely.
   - Calculates hashes.
   - No execution permitted.

3. Static Analysis Zone
   - Strings, file type detection, hash enrichment, metadata extraction.
   - No detonation.

4. Detonation Zone
   - Disposable containers or VMs.
   - No root execution.
   - Egress controlled.
   - Heavy monitoring.

5. Services Zone
   - Fake DNS.
   - Fake HTTP services.
   - Packet capture.
   - Optional controlled proxy.

6. Detection Engineering Zone
   - yarGen.
   - YARA validation.
   - IOC normalization.
   - Sigma/SIEM rule drafting.

7. Reporting Zone
   - Clean final outputs.
   - Markdown/text reports.
   - Rule repository.

Trust boundaries
----------------

Boundary 1: Internet -> Intake
  Only approved pull scripts and APIs should be allowed.

Boundary 2: Intake -> Detonation
  Samples move one way into execution jobs.

Boundary 3: Detonation -> Reporting
  Only artifacts and logs are exported.

Boundary 4: Lab -> Analyst workstation
  No raw malware should be copied back to a personal workstation unless there is
  a strict business need and approved handling process.

Container safety baseline
-------------------------

Use these defaults unless there is a deliberate reason not to:

- run as non-root user
- disable privileged mode
- drop Linux capabilities
- use read-only root filesystem where possible
- no host Docker socket mount
- no host filesystem mounts except dedicated sample/artifact directories
- no shared credentials inside containers
- one sample per disposable execution environment
- explicit resource limits
- explicit network segmentation

Example data flow
-----------------

1. Analyst starts job.
2. Intake downloads sample.
3. Intake calculates SHA256.
4. Sample is stored under sample_store/SHA256/.
5. Static analysis extracts metadata.
6. Optional ANY.RUN or UnpacMe analysis is attached to job record.
7. Detonation container starts.
8. Sensors start.
9. Sample executes.
10. Sensors stop.
11. Artifacts export.
12. Container is destroyed.
13. yarGen creates candidate YARA.
14. Analyst validates detections.
15. Final report is written.
